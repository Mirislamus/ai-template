# Стандарты качества и технический чеклист приемки

Документ определяет объективные технические критерии качества, которым обязан соответствовать каждый проект перед сдачей и деплоем в продакшен. Он не диктует визуальный стиль, а задает инженерную планку стабильности, скорости и бездефектности.

---

## 1. Чеклист стабильности и геометрии верстки

Каждая страница обязана пройти 4 теста геометрии:

1. **Тест на отсутствие горизонтального скролла (No Overflow-X):**
   - На любых разрешениях в диапазоне от **360px до 1920px** горизонтальная полоса прокрутки категорически отсутствует.
   - **Запрет:** категорически запрещено маскировать выпирающие элементы костылем `body { overflow-x: hidden; }`. Любое переполнение устраняется исправлением ширины конкретного блока или картинки.
2. **Тест непрерывной резиновости (Fluid Viewport Check):**
   - При плавном сужении или расширении окна браузера (включая нестандартные размеры вроде 412px, 820px, 1050px) верстка не должна «ломаться», текст не должен налезать на соседние блоки, а элементы не должны выпадать из контейнеров.
3. **Тест масштабирования текста (Zoom 200% / WCAG):**
   - При увеличении масштаба страницы в браузере до 200% верстка сохраняет целостность, текст остается читаемым и не обрезается краями контейнеров.
4. **Стресс-тест динамического контента:**
   - Проверка блоков на длинные строки без пробелов (длинные ссылки, email): они не должны разрывать сетку благодаря `overflow-wrap: anywhere;`.
   - Проверка карточек на отсутствие картинок (корректность фоллбэк-заглушек).

## 2. Метрики производительности и Google Lighthouse

Перед публикацией страница тестируется в режиме мобильного аудита Google Lighthouse (профиль Mobile / замедленная сеть и процессор).

### Минимальные пороги прохождения (Quality Gate). Это единственный источник порогов, остальные документы ссылаются сюда:
- **Performance (Производительность):** **≥ 90** (для статичных страниц Astro целевой ориентир — **95–100**).
- **Accessibility (Доступность):** **≥ 95** (контрастность текста по WCAG AA ≥ 4.5:1, наличие alt-атрибутов, иерархия заголовков, видимый фокус).
- **Best Practices (Лучшие практики):** **= 100** (HTTPS, актуальные веб-стандарты, отсутствие ошибок консоли, безопасные внешние ссылки).
- **SEO (Поисковая оптимизация):** **= 100** (наличие title, description, canonical, robots.txt, валидный sitemap).

### Нормативы Core Web Vitals:
- **LCP (Largest Contentful Paint):** **≤ 2.5 секунды** (главный баннер первого экрана отрисовывается без задержки благодаря `loading="eager"` и `fetchpriority="high"`).
- **CLS (Cumulative Layout Shift):** строго **0.00** (полное отсутствие скачков макета при загрузке картинок за счет явных `width`/`height` или `aspect-ratio`).
- **INP (Interaction to Next Paint):** **≤ 200 мс** (полевая метрика отзывчивости; в лаборатории контролируется через TBT).
- **TBT (Total Blocking Time):** **≤ 150–200 мс** — лабораторный ориентир (минимальное время блокировки основного потока за счет отложенной аналитики и легковесных скриптов).

## 3. Матрица кроссбраузерной совместимости

Проект обязан функционировать без визуальных и логических дефектов в последних 2 стабильных версиях ключевых браузерных движков:

1. **Chromium (Blink):** Google Chrome, Microsoft Edge, Яндекс.Браузер, Opera (десктоп и Android).
2. **WebKit (Apple):** Safari на macOS, Safari на iOS (iPhone / iPad).
   - **Специфика iOS:**
     - Отсутствие принудительного автозума при клике в поле ввода (размер шрифта инпутов строго `16px`).
     - Корректная высота экрана мобильного браузера через единицу `100dvh` вместо устаревшего `100vh`.
     - Корректная плавная прокрутка и отсутствие залипания hover-стилей при тапе (изоляция миксином `hover`, [ADR 0003](decisions/0003-scss-standards.md) §5).
3. **Gecko (Mozilla):** Mozilla Firefox (десктоп).

*Устаревшие браузеры (Internet Explorer, старые версии Safari/Chrome старше 3 лет) не поддерживаются во избежание раздувания бандла полифилами.*

## 4. Чистота консоли и целостность ссылок

- **Ноль ошибок в DevTools консоли:**
  - При первой загрузке, переходах по страницам, открытии модалок и заполнении форм в консоли браузера должно быть **ровно 0 ошибок** (`console.error`, сетевые сбои 404, необработанные исключения промисов).
  - Отсутствие предупреждений (warnings) от React о некорректных DOM-пропсах или ключах списков.
- **Целостность ссылок (Link Integrity):**
  - Запрещены пустые заглушки `href="#"`.
  - Все якорные ссылки (`#faq`, `#contact`) ведут на реально существующие `id` элементов на странице.
  - Все телефонные номера обернуты в валидные ссылки `tel:+79991234567` (только международный формат с знаком `+` и цифрами).
  - Email-адреса обернуты в ссылки `mailto:example@domain.ru`.
  - Внешние ссылки открываются в новой вкладке строго с атрибутом `rel="noopener noreferrer"`.

## 5. Итоговый конвейер статических проверок

Перед коммитом или релизом проект обязан успешно пройти единый автоматический конвейер:

```bash
bun run check
```

Состав команды:
1. `prettier --check` — форматирование всех файлов соответствует стандарту.
2. `eslint . --max-warnings 0` — ноль ошибок и ворнингов в JavaScript/TypeScript.
3. `stylelint "src/**/*.{css,scss}" --max-warnings 0` — ноль ошибок в SCSS Modules.
4. `astro check` (или `tsc --noEmit`) — 100% строгая проверка типов без единой ошибки.
