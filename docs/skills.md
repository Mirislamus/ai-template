# Регламент использования AI-навыков (docs/skills.md)

Документ определяет разделение одобренных AI-навыков (Skills) на обязательные этапы жизненного цикла (Core Pipeline) и специализированные инструменты по требованию (On-Demand), а также протокол отчетности.

---

## 1. Протокол использования навыков (Lifecycle & Reporting)

Любой AI-агент при выполнении задачи в репозитории обязан следовать строгому двухэтапному протоколу:

### Этап 1: Декларация на старте задачи (Before Work)
- В самом первом сообщении turn-цикла агент **обязан явно объявить**, какие навыки он планирует задействовать и с какой целью:
  - *Пример:* «Для выполнения задачи будут использованы скилы: `$figma` (для извлечения параметров макета), `$emil-design-eng` (для полировки состояний кнопки) и `$code-review` (для финальной проверки перед сдачей)».
- Если задача тривиальна (исправление опечатки, документация) и навыки не требуются, агент явно пишет: *«Скилы не требуются»*.

### Этап 2: Фиксация в финальном отчете (After Work)
- В итоговом отчете по стандарту [AGENTS.md](../AGENTS.md) агент обязан включить секцию:
  - **Использованные скилы:** список фактически примененных навыков и конкретный результат их использования (например: *«`$emil-design-eng`: применены микро-трансформации `transform: scale(0.98)` для тактильного отклика при клике»*).

## 2. Приоритет стандартов проекта (Strict Precedence)

Инструкции репозитория ([AGENTS.md](../AGENTS.md), [docs/design.md](design.md) и реестр [docs/decisions/](decisions/)) имеют **абсолютный приоритет** над любыми рекомендациями скилов:
- Если скил рекомендует Tailwind CSS — **запрещено** (строго SCSS Modules по [ADR 0003](decisions/0003-scss-standards.md)).
- Если скил рекомендует Radix UI / Headless UI — **запрещено** (строго нативный `<dialog>`, `<details>` по [ADR 0002](decisions/0002-html-standards.md) и [ADR 0010](decisions/0010-third-party-libraries-policy.md)).
- Если скил рекомендует `rem`/`em` для отступов — **запрещено** (строго 8pt Grid на пикселях `px` по [docs/design.md](design.md)).

## 3. Обязательные скилы жизненного цикла (Core Pipeline)

Используются последовательно на основных этапах работы над задачей:

### 1. Этап проектирования и старта:
- **`$grilling`** — обязательный допрос пользователя перед началом проектирования продукта, архитектурных развилок или сложных фичей. Задает вопросы строго по одному с аргументированными рекомендациями.

### 2. Этап разработки интерфейса и логики:
- **`$figma`** — извлечение дизайн-токенов, векторных ассетов и параметров макета из Figma для 1:1 переноса в SCSS Modules (при наличии макета).
- **`$impeccable`** — глубокий UX-аудит, визуальная иерархия, информационная архитектура, проработка состояний интерфейса (Loading, Empty, Error) и устранение визуального шума.
- **`$emil-design-eng`** — инженерная полировка микровзаимодействий: тактильные hover/active отклики, оптические выравнивания иконок, естественные переходы и микродвижения интерфейса.
- **`$vercel-react-best-practices`** — аудит производительности React-компонентов: исключение лишних ререндеров, предотвращение утечек памяти и чистота хуков по [ADR 0005](decisions/0005-react-standards.md).

### 3. Этап проверки и сдачи:
- **`$agent-browser`** — сквозная проверка интерфейса в реальном браузере: отсутствие ошибок в DevTools консоли, отсутствие горизонтального скролла на 360px, проверка доступности и работы форм.
- **`$code-review`** — обязательное двухфакторное ревью кода перед коммитом (соответствие 18 ADR репозитория и соответствие спецификации задачи).

## 4. Специализированные скилы по требованию (On-Demand)

Подключаются агентом строго при возникновении специализированных задач:

- **`$imagegen`** — генерация растровых иллюстраций, текстур и заглушек при отсутствии готового фотобанка у клиента (с последующей оптимизацией в AVIF/WebP по [ADR 0007](decisions/0007-assets-and-media.md)).
- **`$research`** — глубокое исследование внешней документации и спецификаций незнакомых API (эквайринг, CRM, Telegram Bot API, внешние интеграции).
- **`$tdd`** — разработка через тестирование для сложной бизнес-логики (схемы валидации Zod, калькуляторы цен, финансовые расчеты) на базе Vitest.
- **`$diagnosing-bugs`** — структурированный цикл локализации и исправления трудноуловимых багов, утечек памяти или просадок FPS.
- **`$resolving-merge-conflicts`** — безопасное пошаговое разрешение конфликтов Git-слияния с сохранением целостности кода по [ADR 0011](decisions/0011-git-workflow-and-commits.md).
- **`$request-refactor-plan`** — составление безопасного пошагового плана рефакторинга крупного модуля на серию атомарных коммитов.
- **`$codebase-design`** — проектирование глубоких и чистых интерфейсов нестандартных модулей по методологии FSD-Lite.
