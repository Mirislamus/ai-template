# ADR 0013: Техническая архитектура поисковой оптимизации (SEO)

## Контекст и цели

Техническое SEO определяет индексируемость, видимость в поиске Яндекса и Google, кликабельность сниппетов (CTR) и защиту от санкций за дублирование контента.
Цели архитектурного стандарта:
1. **Защита от дублей страниц:** строгая нормализация слэшей (`trailingSlash: 'never'`) с 301-редиректом и абсолютные канонические URL (`canonical`).
2. **Автоматизация карты сайта и инструкций краулерам:** сборка актуального `sitemap.xml` на этапе билда и динамический `robots.txt`.
3. **Семантическая микроразметка Schema.org:** использование формата **JSON-LD** для расширенных сниппетов (`Organization`, `BreadcrumbList`, `FAQPage`, `Product`).
4. **Строгая типобезопасность схем:** использование словаря типов `schema-dts` для предотвращения опечаток в полях.
5. **Многоуровневая верификация:** локальная проверка структуры + обязательный аудит в Schema.org Validator и Google Rich Results Test на боевом домене после деплоя.
6. **Региональность и мультиязычность:** строгие перекрестные ссылки `hreflang` с версией `x-default` и физическими URL.

## Принятые стандарты

### 1. Канонические URL и нормализация слэшей

- **Нормализация концевого слэша (`trailingSlash: 'never'`):**
  - В проекте фиксируется единый формат адресов **без слэша на конце** (`https://site.ru/services`).
  - Запросы с закрывающим слэшем (`/services/`) автоматически редиректятся через постоянный 301-редирект на адрес без слэша (конфигурация сервера — [ADR 0018](../common/0018-deployment-and-caching.md) §3).
  - В Astro: `trailingSlash: 'never'` совместно с `build: { format: 'file' }` (страница `/services` собирается в `services.html`).
  - Исключение: корень домена записывается со слэшем (`https://domain.ru/`).
- **Обязательный абсолютный тег `<link rel="canonical">`:**
  - Присутствует в `<head>` на каждой странице сайта.
  - Формируется как полный абсолютный адрес без UTM-меток, сессионных параметров и хешей:
    ```html
    <link rel="canonical" href="https://domain.ru/catalog/product-name">
    ```
  - Это защищает от санкций за дублированный контент при рекламных кампаниях и склеивает поисковый вес.

---

### 2. Автоматическая генерация `sitemap.xml` и `robots.txt`

- **Карта сайта (`sitemap.xml`):**
  - В Astro: генерация на этапе сборки через плагин `@astrojs/sitemap` с обязательным указанием базового домена в конфиге (`site: 'https://domain.ru'`).
  - В Next.js: генерация через `app/sitemap.ts`.
  - **Исключения:** из карты сайта автоматически исключаются страницы `/404`, `/api/*`, `/admin/*`, технические подтверждения заявок (`/success`).
  - Поле `lastmod` генерируется автоматически на основе даты изменения файла в Git или даты публикации в CMS.
- **Файл инструкций (`robots.txt`):**
  - Разрешает индексацию полезного контента: `Allow: /`.
  - Запрещает служебные директории: `Disallow: /api/`, `Disallow: /admin/`.
  - Обязательно содержит прямую абсолютную ссылку на индексную карту сайта:
    ```text
    User-agent: *
    Allow: /
    Disallow: /api/

    Sitemap: https://domain.ru/sitemap-index.xml
    ```

### 3. Микроразметка Schema.org: формат JSON-LD и `schema-dts`

- **Строго формат JSON-LD:**
  - Микроразметка внедряется через отдельный тег в `<head>`:
    ```html
    <script type="application/ld+json">
      { ... }
    </script>
    ```
  - Запрещено засорять HTML-разметку устаревшими атрибутами Microdata (`itemscope`, `itemprop`).
- **Типобезопасность через `schema-dts`:**
  - Для генерации объектов микроразметки используются официальные строгие типы `schema-dts`.
  - Исключаются опечатки в свойствах (`acceptedAnswer`, `priceCurrency`, `itemOffered`) на этапе компиляции.
- **Базовые схемы (на всех проектах):**
  1. **`Organization` / `LocalBusiness`:** название бренда, логотип, адрес, контактный телефон, режим работы, профили социальных сетей.
  2. **`WebSite`:** привязка домена и названия сайта. `SearchAction` не используется: поисковое окно в сниппете Google больше не показывается.
  3. **`BreadcrumbList`:** хлебные крошки для формирования аккуратных навигационных цепочек в поисковой выдаче.
- **Специализированные контентные схемы:**
  - Для секций вопрос-ответ: **`FAQPage`** — семантическая разметка блока. Google отключил FAQ rich results, поэтому расширенного сниппета она не дает; разметка добавляется, только если блок FAQ есть на странице, и проверяется в Schema.org Validator.
  - Для статей и новостей: **`Article`** или **`BlogPosting`** (автор, дата публикации, превью).
  - Для каталогов и карточек: **`Product`** + **`Offer`** (цена, валюта, статус наличия).

---

### 4. Инструменты валидации микроразметки и расширенных сниппетов

- **Локальный контроль:**
  - Автоматическая проверка валидности синтаксиса генерируемого JSON-LD (отсутствие `undefined`, битых кавычек).
- **Обязательная пост-деплой верификация в браузере (Production Verification):**
  - После деплоя на боевой домен проводится аудит живых страниц:
    1. **Google Rich Results Test (search.google.com/test/rich-results):** подтверждение права на расширенный сниппет в Google (зеленый статус для типов, которые поддерживает Google: хлебные крошки, `Product`, `Organization` / `LocalBusiness`; `FAQPage` в этом инструменте не проверяется).
    2. **Schema.org Validator (validator.schema.org):** подтверждение отсутствия структурных ошибок в графе сущностей.

---

### 5. Мультиязычность и региональность (`hreflang`)

- **Языковой атрибут документа:**
  - Тег `<html>` обязан содержать валидный языковой код: `<html lang="ru">` (или `"en"`).
- **Связка языковых версий (`hreflang`):**
  - При наличии 2 и более локализаций каждая страница обязана содержать двусторонние ссылки на свои языковые копии:
    ```html
    <link rel="alternate" hreflang="ru" href="https://domain.ru/page">
    <link rel="alternate" hreflang="en" href="https://domain.ru/en/page">
    <link rel="alternate" hreflang="x-default" href="https://domain.ru/page">
    ```
  - Директива `x-default` обязательна и указывает на базовую версию сайта для пользователей из неперечисленных стран.
- **Физические URL для локализаций:**
  - Каждая языковая версия обязана иметь уникальный URL (`/en/...`). Запрещено переключать язык налету через JS без изменения адресной строки.
