# ADR 0007: Оптимизация медиа, изображений, шрифтов и ассетов

## Контекст и цели

Медиафайлы (картинки, шрифты, видео, иконки) составляют до 70–80% общего веса веб-страницы и являются главным фактором ухудшения метрик Core Web Vitals:
- **LCP (Largest Contentful Paint):** задержка загрузки главного баннера первого экрана.
- **CLS (Cumulative Layout Shift):** скачки верстки из-за отсутствия зарезервированных размеров изображений.
- **FOIT / FOUC:** мигание невидимого или нестилизованного текста при загрузке шрифтов.

Цели архитектурного стандарта:
1. **Максимальное сжатие графики:** использование современных форматов AVIF и WebP вместо устаревших PNG/JPEG.
2. **Нулевой сдвиг макета (Zero CLS):** обязательные размеры `width` и `height` или `aspect-ratio` для всех медиа-элементов.
3. **Оптимизация первого экрана:** `loading="eager"` и `fetchpriority="high"` для LCP-элемента; строгий `loading="lazy"` для всего остального.
4. **Самохостинг шрифтов:** отказ от внешних Google Fonts CDN в пользу локальных WOFF2 с `font-display: swap` и точечным `preload`.
5. **Чистая векторная графика:** использование `lucide-react` для UI-иконок и обязательная оптимизация SVGO для локальных SVG.
6. **Современный набор фавиконок:** поддержка темной темы в `favicon.svg` и стандартизированный OpenGraph (1200×630 px).

## Принятые стандарты

### 1. Форматы растровых изображений и адаптивность

- **Форматы графики:**
  - **AVIF** — основной и наиболее эффективный формат сжатия (экономия до 50% веса по сравнению с JPEG/WebP без потери качества).
  - **WebP** — обязательный fallback-формат для браузеров без поддержки AVIF.
  - **PNG / JPEG** — запрещены в финальной разметке. Исключения: `og:image` (мессенджеры не читают AVIF/WebP), `apple-touch-icon.png`, `<img>`-фоллбэк внутри `<picture>` и диаграммы с попиксельной резкостью; исходники в репозитории до сборки не ограничиваются.
- **Оптимизация средствами фреймворка:**
  - В профиле Astro: использовать нативный компонент `<Picture />` или `<Image />` из `astro:assets`.
  - В профиле Next.js: использовать встроенный компонент `next/image`.
- **Адаптивные размеры (`sizes`):**
  - Для изображений, меняющих ширину в зависимости от экрана, обязателен атрибут `sizes` (например, `sizes="(width < 768px) 100vw, 50vw"`), предотвращающий загрузку десктопных ассетов на мобильные устройства.

### 2. Стратегия загрузки изображений и защита от CLS

- **Главное изображение первого экрана (Hero / LCP элемент):**
  - **Категорически запрещен** атрибут `loading="lazy"`.
  - **Обязательно:** `loading="eager"` + `fetchpriority="high"` + `decoding="async"`.
  - При необходимости — предзагрузка в `<head>`:
    ```html
    <link rel="preload" as="image" href="..." fetchpriority="high" type="image/avif">
    ```
- **Изображения ниже первого экрана (Below the fold):**
  - **Обязательно:** нативный `loading="lazy"` + `decoding="async"`.
  - Запрещено использовать сторонние тяжелые JavaScript-библиотеки для lazy-load.
- **Тотальная защита от CLS (Zero Layout Shift):**
  - Каждое изображение **обязано** иметь явные целочисленные атрибуты `width` и `height` (соответствующие пропорциям файла) либо CSS-свойство `aspect-ratio`.
  - Браузер обязан вычислить соотношение сторон и зарезервировать место в макете до начала загрузки байтов по сети.

### 3. Шрифты и типографика (Web Fonts)

- **Формат шрифтов:** строго **`woff2`**. Форматы `ttf`, `otf`, `eot`, `woff` запрещены.
- **Тотальный запрет внешних CDN (Google Fonts / Typekit):**
  - Шрифты хранятся строго локально в проекте (`public/fonts/`, URL `/fonts/...`).
  - Исключаются сторонние DNS-запросы, блокировка рендеринга и проблемы с приватностью (GDPR).
- **Правило объявления `@font-face`:**
  - Обязательно: свойство `font-display: swap;` для мгновенного показа текста системным шрифтом до загрузки кастомного.
  - Подключение системного fallback-шрифта со сходными метриками.
- **Предзагрузка критического шрифта (Preload):**
  - В `<head>` предзагружается **строго одно главное начертание** (обычно Regular 400 основного текста):
    ```html
    <link rel="preload" href="/fonts/inter-regular.woff2" as="font" type="font/woff2" crossorigin>
    ```
  - Запрещено предзагружать второстепенные начертания (Bold, Italic, SemiBold), чтобы не создавать конкуренцию за сеть на старте.
- **В Next.js:** использовать встроенный модуль `next/font/local` (автоматический самохостинг и оптимизация сдвига метрик шрифта).

### 4. Векторная графика (SVG) и иконки

- **Интерфейсные UI-иконки:**
  - Строго библиотека **`lucide-react`**.
  - Именованный точечный импорт (`import { ArrowRight, Check } from 'lucide-react'`) для чистого tree-shaking.
  - Единые системные пропорции (`size={20}`, `strokeWidth={2}`).
- **Брендовые иллюстрации и логотипы:**
  - Хранятся локально в `src/assets/icons/` или `src/assets/images/`.
  - **Обязательная оптимизация через SVGO:** удаление редакторских метаданных, мусора Figma/Illustrator, лишних путей и комментариев.
  - **Способ подключения:**
    - Управляемые по цвету иконки: инлайновый SVG-компонент с `fill: currentColor` или `stroke: currentColor` и атрибутом `aria-hidden="true"`.
    - Крупные статичные векторные иллюстрации/схемы: стандартный тег `<img src="..." alt="..." width="..." height="...">`, чтобы не раздувать размер HTML-документа.
- **Запрет иконочных шрифтов:** FontAwesome и любые glyph-шрифты запрещены.

### 5. Фавиконки и графика социальных сетей (OpenGraph)

- **Минимальный современный комплект фавиконок:**
  1. `favicon.ico` (32×32) в корне `public/` — для устаревших клиентов и поисковых ботов.
  2. `favicon.svg` в `public/` — векторная масштабируемая фавиконка с поддержкой светлой и темной темы через CSS:
     ```xml
     <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
       <style>
         @media (prefers-color-scheme: dark) { :root { fill: #ffffff; } }
         @media (prefers-color-scheme: light) { :root { fill: #000000; } }
       </style>
       <!-- path -->
     </svg>
     ```
  3. `apple-touch-icon.png` (180×180) в `public/` — для ярлыков Safari / iOS.
  4. `site.webmanifest` — базовый манифест с иконками 192×192 и 512×512.
- **Превью для соцсетей (OpenGraph / Twitter Card):**
  - Наличие тегов `og:image` и `twitter:image` обязательно для каждой страницы.
  - Стандартное разрешение: строго **`1200 × 630 px`**.
  - **Абсолютный URL:** ссылка обязана содержать протокол и домен (`https://domain.ru/og-cover.jpg`), иначе социальные сети и мессенджеры (Telegram, VK, WhatsApp) не смогут отрисовать карточку.
