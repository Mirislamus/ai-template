# ADR 0015: Аналитика, отслеживание целей и производительность счетчиков

## Контекст и цели

Подключение счетчиков веб-аналитики (Яндекс.Метрика, Google Analytics 4) необходимо для бизнеса, но классическая синхронная вставка скриптов в `<head>` обваливает показатели Core Web Vitals и снижает конверсию из-за блокировки потока (TBT).
Цели архитектурного стандарта:
1. **Идеальный Lighthouse при наличии аналитики:** отложенная инициализация счетчиков без блокировки рендера и первого экрана.
2. **Защита от сбоев и AdBlock:** централизованный типобезопасный фасад `trackEvent`, исключающий падения приложения при заблокированных скриптах.
3. **Чистый код без разбросанных ID:** хранение идентификаторов счетчиков в переменных окружения и централизация типов целей.
4. **Правовое соответствие (152-ФЗ / GDPR):** легковесный ненавязчивый баннер `CookieConsent` с сохранением статуса в `localStorage`.

## Принятые стандарты

### 1. Стратегия загрузки счетчиков аналитики

- **Запрет синхронной вставки в `<head>`:**
  - Категорически запрещено подключать тяжелые скрипты аналитики (`tag.js`, `gtag.js`) синхронно на старте документа.
- **Отложенная загрузка по первому взаимодействию:**
  - Инициализация счетчиков откладывается до первого пользовательского события:
    ```ts
    const interactionEvents = ['scroll', 'mousemove', 'touchstart', 'keydown'];
    ```
  - Если пользователь не совершил действий, скрипт загружается в фоновом режиме через `requestIdleCallback` (с задержкой 3–4 секунды после полной загрузки страницы).
- **Результат:** браузер успевает отрисовать первый экран (LCP) с нулевым временем блокировки (Total Blocking Time = 0 мс), после чего счетчик собирает полноценную статистику по активной аудитории.

### 2. Типизированный фасад аналитики: `trackEvent`

- **Размещение:** `src/shared/lib/analytics/track-event.ts`.
- **Категорический запрет прямых вызовов:**
  - Запрещено писать `window.ym(...)` или `window.gtag(...)` напрямую внутри JSX-компонентов и обработчиков кликов.
- **Структура фасада с дискриминантными типами:**
  ```ts
  import { env } from '@/shared/config/env';

  export type AnalyticsEvent =
    | { name: 'lead_form_submit'; payload: { formId: string } }
    | { name: 'phone_click'; payload: { location: string } }
    | { name: 'modal_open'; payload: { modalId: string } };

  export function trackEvent<T extends AnalyticsEvent>(event: T): void {
    // Безопасная отправка в Яндекс.Метрику (защита от падения при AdBlock)
    if (typeof window !== 'undefined' && typeof window.ym === 'function' && env.PUBLIC_YM_ID) {
      window.ym(Number(env.PUBLIC_YM_ID), 'reachGoal', event.name, event.payload);
    }

    // Безопасная отправка в Google Analytics 4
    if (typeof window !== 'undefined' && typeof window.gtag === 'function') {
      window.gtag('event', event.name, event.payload);
    }
  }
  ```
- **Использование в компонентах:**
  ```tsx
  trackEvent({
    name: 'lead_form_submit',
    payload: { formId: 'hero-callback' },
  });
  ```

### 3. Согласие на обработку Cookie (Cookie Consent)

- **Размещение:** `src/features/cookie-consent/CookieConsent.tsx`.
- **Поведение:**
  - Ненавязчивая плашка в нижней части экрана с кратким понятным текстом и кнопкой «Понятно» / «Принять».
  - Статус согласия сохраняется в `localStorage` (`cookie_consent_accepted: 'true'`).
  - Повторно баннер не отображается, если ключ уже записан.
- **Загрузка:** монтируется в Astro через директиву `client:idle`, чтобы не задерживать интерактивность первого экрана.
