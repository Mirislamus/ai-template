# ADR 0006: Архитектура управления состоянием (State Management)

## Контекст и цели

Управление состоянием определяет предсказуемость, скорость рендеринга и удобство использования интерфейса.
Цели архитектурного стандарта:
1. **Четкое разделение уровней ответственности:** запрет выноса локального UI-состояния в глобальные хранилища.
2. **URL как единственный источник истины (SSOT):** состояние фильтров, табов, поиска и пагинации должно легко сохраняться в закладках и пересылаться ссылкой.
3. **Эффективный межостровной стейт в Astro:** использование легковесных атомов **Nano Stores** с префиксом `$` и изолированными экшенами.
4. **Производительный глобальный стейт в Next.js:** использование **Zustand** с обязательными точечными селекторами для предотвращения паразитных ререндеров.
5. **Персистентность и кросс-вкладочность:** безопасная синхронизация корзины/настроек через `localStorage` с поддержкой события `storage` и защитой от падений в приватном режиме браузера.

---

## Принятые стандарты

### 1. Четырехуровневая классификация состояния

Любое состояние приложения строго классифицируется по одному из 4 уровней:

1. **Локальный UI-стейт (Local State):**
   - Данные, существующие строго в рамках одного компонента (открытие выпадающего списка, временный ввод текста, состояние тултипа).
   - Инструменты: нативные хуки `useState` или `useReducer`.
   - **Правило:** категорически запрещено выносить локальный UI-стейт в глобальные сторы.
2. **Состояние в URL (URL State / URL as Single Source of Truth):**
   - Параметры, определяющие текущий вид и выборку страницы (фильтры каталога, активная вкладка табов, номер страницы, поисковый запрос, сортировка).
   - Инструменты: `URLSearchParams`, хуки навигации фреймворка (`useSearchParams`, `useRouter`).
   - **Правило:** если состояние должно восстанавливаться при обновлении страницы, нажатии кнопки «Назад» в браузере или пересылке ссылки — оно обязано храниться в URL.
3. **Совместное клиентское состояние (Shared Client State):**
   - Данные, необходимые одновременно нескольким изолированным компонентам или разным островам архитектуры (корзина товаров, список избранного, глобальная модалка заявки, счетчик уведомлений).
   - Инструменты: **Nano Stores** (в профиле Astro) или **Zustand** (в профиле Next.js).
4. **Серверное состояние и кеш данных (Server State):**
   - Данные, полученные по сети с сервера или из CMS.
   - Инструменты: статическая генерация (SSG/ISR), нативный Fetch Cache в Next.js App Router и **TanStack Query** для клиентских выборок и мутаций ([ADR 0008](0008-forms-and-api.md) §2).
   - **Правило:** не дублировать серверные данные в клиентские сторы без необходимости локальных мутаций.

### 2. Межостровное состояние в Astro: Nano Stores

- **Размещение:** `src/shared/stores/` (или внутри конкретной фичи, например `src/features/cart/model/cart.store.ts`).
- **Обязательный префикс `$`:**
  - Название экспортируемого реактивного атома **обязано начинаться со знака `$`** (`$cart`, `$isLeadModalOpen`, `$theme`, `$favoriteIds`). Это визуально отличает стор от обычной переменной.
- **Типы хранилищ:**
  - Простые примитивы: `atom<boolean>(false)`.
  - Структуры и словари: `map<CartState>({ items: [] })`.
  - Производный вычисляемый стейт: `computed([$cart], cart => calculateTotal(cart))`.
- **Подписка в React Islands:**
  - Использовать официальный хук `useStore` из `@nanostores/react`:
    ```tsx
    import { useStore } from '@nanostores/react';
    import { $cart, addToCart } from '@/shared/stores/cart.store';

    export function CartCounter() {
      const cart = useStore($cart);
      return <span>{cart.items.length}</span>;
    }
    ```
- **Мутации состояния (Экшены):**
  - Запрещено вызывать методы `$store.set()` напрямую в JSX обработчиках.
  - Изменения оформляются как экспортируемые чистые функции-экшены рядом со стором (`addToCart(item)`, `clearCart()`).

### 3. Глобальное состояние в Next.js: Zustand

- **Размещение:** `src/shared/stores/` (или в слое модели фичи).
- **Назначение:** Zustand хранит только клиентское состояние (UI, корзина, настройки). Данные сервера живут в Server Components или TanStack Query.
- **Именование:** хук с префиксом `use` + сущность + `Store` (`useCartStore`, `useUserStore`).
- **Обязательное использование точечных селекторов:**
  - **Категорически запрещено** вызывать стор целиком без селектора:
    ```tsx
    // ❌ Запрещено: компонент ререндерится при любом изменении любого поля стора
    const { items, totalPrice } = useCartStore();
    ```
  - **Обязательно:** точечная подписка на нужные поля (или через `useShallow`):
    ```tsx
    // ✅ Правильно: ререндер строго при изменении массива items
    const items = useCartStore(state => state.items);
    const addItem = useCartStore(state => state.actions.addItem);
    ```
- **Структура стейта и экшенов:**
  - Экшены группируются внутри поля `actions`:
    ```ts
    type CartState = {
      items: CartItem[];
      actions: {
        addItem: (item: CartItem) => void;
        removeItem: (id: string) => void;
      };
    };
    ```
- **Персистентность (Persist Middleware):**
  - Использовать `partialize`, чтобы сохранять в `localStorage` только критичные данные (исключая флаги `isLoading`, ошибки и временные таймеры).

### 4. Стандарты работы с URL (URL as Single Source of Truth)

- **Синхронизация параметров:**
  - При загрузке страницы UI-контролы (селекты, чекбоксы фильтра, инпут поиска) инициализируют свое значение из параметров строки запроса (`URLSearchParams`).
  - Запрещено хранить копию параметров URL в локальном стейте без синхронизации.
- **Запись параметров в URL:**
  - **Поиск по тексту:** ввод дебаунсится (300–400 мс) и записывается через `replaceState` (или `router.replace`), чтобы не создавать новую запись в истории на каждый символ.
  - **Выбор фильтра / таба:** записывается через `pushState` (или `router.push`), позволяя пользователю вернуться назад кнопкой браузера.
  - **Сохранение скролла:** передавать флаг `{ scroll: false }`, предотвращая прыжок экрана наверх при клике на фильтр.
  - **Автосброс пагинации:** при любом изменении фильтров или поискового запроса параметр `page` автоматически сбрасывается на 1 (или удаляется из URL).

---

### 5. Персистентность и кросс-вкладочная синхронизация

- **Синхронизация между вкладками:**
  - Хранилища, сохраняемые в `localStorage` (корзина, избранное), обязаны слушать браузерное событие `storage` (`window.addEventListener('storage', ...)`), чтобы изменения, сделанные на одной вкладке, мгновенно отображались на остальных открытых вкладках.
  - В Astro: использовать `@nanostores/persistent` с параметром `listen: true`.
  - В Next.js: middleware `persist` в Zustand сам не синхронизирует вкладки, поэтому добавляется слушатель события `storage` с повторной гидратацией:
    ```ts
    window.addEventListener('storage', event => {
      if (event.key === 'cart-storage') void useCartStore.persist.rehydrate();
    });
    ```
- **Защита от сбоев хранилища (Private Browsing / Quota):**
  - Любые обращения к `localStorage` обязаны быть изолированы в безопасных обертках с блоком `try/catch` и безопасным fallback-хранением в оперативной памяти (актуально для приватного режима Safari и переполнения квоты).
