# ADR 0010: Политика управления сторонними зависимостями и библиотеками

## Контекст и цели

Бесконтрольное добавление npm-пакетов (dependency bloat) — главная причина падения скорости загрузки сайта, деградации безопасности и накопления технического долга.
Цели архитектурного стандарта:
1. **Принцип максимальной свежести (Latest Stable):** использование самых актуальных стабильных версий библиотек и спецификаций ECMAScript (ES2023–ES2025+) на дату старта проекта.
2. **Защита от устаревания и уязвимостей:** фиксация lockfile в Git (`bun.lock`), регулярный аудит безопасности.
3. **Бескомпромиссный черный список:** запрет тяжелых UI-библиотек, устаревших утилит и монструозных анимационных пакетов с обязательной заменой на нативные веб-стандарты.
4. **Четкий белый список:** реестр легковесных, проверенных и типобезопасных инструментов, одобренных к применению без согласования.
5. **Строгий 4-шаговый протокол аудита:** процедура обоснования добавления новых зависимостей (лимит веса < 10–15 Кб gzipped, ESM, Tree-shaking).

## Принятые стандарты

### 1. Политика версий и актуальности (Always Fresh / Latest Stable)

- **Самые актуальные стабильные версии на дату создания проекта:**
  - При инициализации проекта или установке новых библиотек ставятся **строго последние актуальные релизы** (`latest`).
  - Запрещено использовать устаревшие мажорные версии фреймворков и библиотек.
  - Запрещены нестабильные пре-релизы (`alpha`, `beta`, `rc`, `canary`) в продакшене без технического согласования.
- **Современные стандарты языка:**
  - Использовать самую современную спецификацию ECMAScript, поддерживаемую текущими стабильными рантаймами (Bun 1.4+ / Node.js 24+) и современными браузерами (Baseline).
- **Контроль блокировок (Lockfile):**
  - Файл блокировок `bun.lock` (или `bun.lockb`) **обязан быть закоммичен в Git**.
  - Это обеспечивает повторяемость и побайтовую идентичность сборок у всех разработчиков и на CI/CD серверах.
- **Регулярный аудит:**
  - Запуск `bun outdated` и `bun update` для своевременного обновления минорных версий.
  - Проверка на известные уязвимости через команду `bun audit`.

### 2. Черный список библиотек (Категорически запрещено)

Использование следующих библиотек запрещено без специального архитектурного исключения:

| Категория | Запрещенные пакеты | Нативная или одобренная альтернатива |
|---|---|---|
| **UI-библиотеки** | MUI, Ant Design, Chakra UI, Semantic UI | SCSS Modules + дизайн-токены |
| **Headless UI** | Radix UI, Headless UI, Ariakit | Нативные теги `<dialog>`, `<details>`, `<summary>`, `<select>` |
| **Утилиты данных** | Lodash, Underscore, Ramda | Нативные методы JS/ES2023+ (`.toSorted()`, `Object.groupBy()`, `structuredClone()`) |
| **Даты и время** | Moment.js, Day.js, date-fns | Нативные объекты `Date`, `Intl.DateTimeFormat`, `Intl.RelativeTimeFormat` |
| **Слайдеры** | Swiper, Slick Carousel, Owl Carousel | Легковесный `embla-carousel` (~7 Кб) |
| **Анимации** | GSAP, Framer Motion, Motion, AOS | CSS Transitions/Keyframes + `IntersectionObserver` |
| **HTTP-клиенты** | Axios, Superagent, Request | `ky` (~3 Кб) поверх нативного Fetch API |
| **Стейт-менеджеры** | Redux, Redux Toolkit, MobX | `Nano Stores` (Astro) и `Zustand` (Next.js) |

### 3. Белый список одобренных библиотек (Approved Stack)

Разрешены к использованию в проекте без дополнительного согласования:

- **UI, иконки и уведомления:**
  - `lucide-react` — легковесные векторные иконки с точечным импортом.
  - `sonner` — быстрые всплывающие тосты.
  - `clsx` — легковесное объединение условных CSS-классов.
- **Интерактивные виджеты:**
  - `embla-carousel` / `embla-carousel-react` — доступные и производительные карусели.
  - `imask` / `react-imask` — маски ввода для телефонов и сумм.
  - `photoswipe` (v5) — точечно для полноэкранного Lightbox при необходимости pinch-to-zoom жестов.
- **Формы и валидация:**
  - `react-hook-form` + `@hookform/resolvers` — управление формами без ререндеров.
  - `zod` — декларативная валидация схем на клиенте и сервере.
- **Сетевой слой и серверный стейт:**
  - `ky` — HTTP-клиент над Fetch API.
  - `@tanstack/react-query` — кэширование, синхронизация и мутации данных.
- **Глобальный клиентский стейт:**
  - `nanostores` + `@nanostores/react` + `@nanostores/persistent` — для связи между Astro Islands.
  - `zustand` — для глобального стейта в Next.js.
- **Отказоустойчивость:**
  - `react-error-boundary` — локализация падений компонентов.

### 4. Протокол аудита для новых библиотек

Если возникла редкая задача, требующая стороннего решения, разработчик обязан выполнить 4 шага проверки до установки пакета:

1. **Проверка платформы (Platform-First):**
   - Доказать, что задача не решается современными возможностями браузера (HTML5 API, CSS, Web API, нативные методы ES2024+) в пределах 20–30 строк кода.
2. **Аудит размера бандла (Bundle Size):**
   - Проверить вес через Bundlephobia или bundlejs.com.
   - **Лимит:** не более **10–15 Кб** gzipped.
   - Пакет обязан быть чистым ESM-модулем и поддерживать полноценный Tree-shaking (не затягивать неиспользуемый код).
3. **Качество и типизация:**
   - Обязательное наличие нативных типов TypeScript (`index.d.ts` в пакете или официальный `@types/...`).
   - Активная разработка (релиз за последние 6–12 месяцев), высокий индекс доверия и отсутствие уязвимостей (`bun audit`).
4. **Явное согласование:**
   - Установка пакета, не входящего в белый список, требует явного согласования с описанием назначения и точного размера бандла.
