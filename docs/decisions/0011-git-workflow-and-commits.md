# ADR 0011: Процесс работы с Git, соглашение о коммитах и правила безопасности

## Контекст и цели

Культура работы с Git определяет чистоту истории проекта, простоту отката изменений и безопасность командной работы.
Цели архитектурного стандарта:
1. **Стандартизация истории через Conventional Commits:** семантические префиксы на английском языке в повелительном наклонении.
2. **Атомарность изменений:** один коммит решает ровно одну изолированную задачу; запрет смешивания фич, рефакторинга и форматирования.
3. **Легковесная модель ветвления GitHub Flow:** стабильная ветка `main`, короткоживущие фиче-ветки с четкими префиксами.
4. **Безопасность истории и данных:** категорический запрет `push --force` в основные ветки, запрет опасных деструктивных сбросов (`reset --hard`) без сохранения.
5. **Изоляция секретов и артефактов:** строгий `.gitignore` без попадания ключей и служебных файлов в репозиторий.

---

## Принятые стандарты

### 1. Формат сообщений коммитов: Conventional Commits

Любое сообщение коммита оформляется строго по спецификации Conventional Commits:

```text
<type>(<scope>): <description>
```

#### Разрешенные типы (`type`):
- `feat:` — добавление новой пользовательской функциональности (блок, форма, страница, модалка).
- `fix:` — исправление ошибки в логике, стилях или разметке.
- `docs:` — изменения в документации (`README.md`, `docs/`, `ADR`).
- `style:` — правки форматирования (Prettier, отступы, точки с запятой) без изменения поведения кода.
- `refactor:` — переработка структуры кода без исправления багов и без добавления фич.
- `perf:` — оптимизация производительности (LCP, CLS, сжатие ассетов, уменьшение бандла).
- `test:` — добавление или изменение тестовых сценариев.
- `chore:` — обновление зависимостей, правка конфигов сборщика, линтеров, Git-скриптов.

#### Правила описания (`description`):
- Строго на **английском языке**.
- В **повелительном наклонении настоящего времени (Imperative mood)**:
  - ✅ `add`, `fix`, `update`, `remove`, `refactor`
  - ❌ `added`, `fixes`, `updating`, `removed`
- Строчные буквы в начале описания, точка в конце **не ставится**.
- Примеры:
  - `feat(lead-form): add phone input mask with unmasked value`
  - `fix(header): resolve mobile menu z-index overflow`
  - `docs(decisions): add ADR 0011 for git workflow`
  - `perf(images): convert hero banners to avif format`

---

### 2. Атомарность коммитов (Atomic Commits)

- **Один коммит — одна логическая задача:**
  - Запрещено коммитить реализацию фичи вместе с массовым форматированием соседних файлов через Prettier.
  - Запрещено смешивать исправление бага с несвязанным рефакторингом архитектуры.
- **Рабочее состояние в каждом коммите:**
  - Запрещено коммитить сломанный код с синтаксическими ошибками или ошибками типов.
  - Команда `bun run check` обязана успешно проходить для каждого создаваемого коммита.
- **Запрет коммитов-дампов:**
  - Запрещено сваливать результат многодневной работы в один коммит (`finish project`). Изменения разбиваются на понятные логические этапы.

---

### 3. Модель ветвления: GitHub Flow

- **Главная ветка (`main`):**
  - Всегда стабильна, собирается без ошибок и отражает текущее рабочее состояние проекта.
- **Именование фиче-веток:**
  - Префикс типа + слэш + название задачи в `kebab-case`:
    - `feat/catalog-filter` — разработка новой фичи.
    - `fix/contact-modal-scroll` — исправление дефекта.
    - `perf/lcp-hero-preload` — оптимизация загрузки.
    - `docs/seo-guidelines` — обновление документации.
    - `refactor/api-client` — внутренний рефакторинг.
- **Короткий жизненный цикл:**
  - Ветка живет не более 1–3 дней, после чего вливается в `main` во избежание тяжелых конфликтов слияния.

---

### 4. Защита репозитория и запрещенные команды

- **Запрет `git push --force` в основные ветки (`main` / `master`):**
  - Для фиче-веток допускается использовать только безопасный флаг `--force-with-lease` (`git push --force-with-lease origin feat/...`).
- **Запрет деструктивного `git reset --hard`:**
  - Запрещено сбрасывать состояние без предварительного сохранения пользовательских изменений через `git stash` или временную ветку.
- **Строгая изоляция секретов (`.gitignore`):**
  - Категорически запрещен коммит файлов `.env`, приватных ключей и паролей.
  - В `.gitignore` обязательно включены:
    - Артефакты сборки: `dist/`, `.astro/`, `.next/`, `out/`.
    - Зависимости: `node_modules/`.
    - Логи и дампы: `*.log`, `npm-debug.log*`, `yarn-debug.log*`.
    - Системный мусор: `.DS_Store`, `Thumbs.db`.
