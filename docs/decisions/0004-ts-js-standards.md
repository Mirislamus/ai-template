# ADR 0004: Стандарты JavaScript и TypeScript

## Контекст и цели

TypeScript и современный JavaScript — фундамент надежности, производительности и поддерживаемости проекта.
Цели стандартов:
1. **Максимальная типобезопасность:** выявление ошибок на этапе компиляции, нулевая толерантность к any и небезопасным приведениям типов.
2. **Предсказуемость и чистота:** единый стиль объявлений, строгий регламент type vs interface, запрет антипаттернов (таких как TS enum).
3. **Производительность рантайма и бандла:** безупречный tree-shaking, отсутствие рантайм-оверхеда, контролируемые фасады (barrel) модулей и избирательная ленивая загрузка тяжелых библиотек.
4. **Читаемость и навигация:** однозначный нейминг файлов, переменных, функций и типов, структурированная группировка импортов.
5. **Отказоустойчивость:** строгая обработка исключений без подавления ошибок, валидация входящих внешних данных (Zod) и безопасные обертки над Web API.

## Принятые стандарты

### 1. Типизация и строгость (Strictness, Any, Type Assertions)

- **Режим компилятора:** `strict: true`, `noImplicitAny: true`, `strictNullChecks: true`.
- **Тотальный запрет `any`:**
  - Использование типа `any` запрещено без исключений.
  - Для внешних, непроверенных или динамических данных (API, параметры URL, JSON, сторонние события) используется строго `unknown`.
  - Преобразование из `unknown` в целевой тип выполняется строго через схемы валидации (Zod) или функции-гарды (`function isItem(val: unknown): val is Item`).
- **Контроль приведений типов (`as`):**
  - Небезопасные утверждения вида `const data = response as User` **запрещены**.
  - Разрешено использование `as const` для создания литеральных неизменяемых структур и констант.
  - Для DOM API вместо приведения используется сужение типа через `instanceof`:
    ```ts
    const input = event.currentTarget;
    if (!(input instanceof HTMLInputElement)) return;
    ```
  - **Полный список допустимых утверждений:** `as const`, `satisfies` и единственная типизированная утилита `getKeys` (§14). Других `as` в прикладном коде быть не должно.

---

### 2. Разделение ролей `type` и `interface`

- **`interface` — только для открытых контрактов и наследования (`extends`):**
  - ООП-контракты сервисов и адаптеров (`implements`).
  - Расширение глобальных типов окружения (Declaration Merging):
    ```ts
    declare global {
      interface Window {
        ym?: (...args: unknown[]) => void;
      }
    }
    ```
  - Расширение контрактов сторонних библиотек при необходимости слияния деклараций.
- **`type` — для всех остальных задач:**
  - Закрытые структуры данных, модели сущностей и DTO.
  - Дискриминантные объединения (Discriminated Unions) и состояния:
    ```ts
    export type RequestState<TData> =
      | { status: 'idle' }
      | { status: 'loading' }
      | { status: 'success'; data: TData }
      | { status: 'error'; errorMessage: string };
    ```
  - Утилитарные типы, трансформации (`Pick`, `Omit`, `ReturnType`) и литеральные типы.

---

### 3. Именование типов и дженериков

- **Регистр:** строго `PascalCase`.
- **Запрет префиксов:**
  - Никаких `I` для интерфейсов (запрещено: `IStorageAdapter`, `IUser`).
  - Никаких `T` для типов (запрещено: `TUserRole`, `TStatus`).
- **Дженерики:**
  - Использовать понятные, семантические имена с префиксом `T` (`TData`, `TValue`, `TError`, `TItem`) вместо одиночных слепых `T`, `K`, `V` (за исключением базовых математических утилит из одной строки).

---

### 4. Константы и перечисления: отказ от `enum`

- **Запрет `enum` и `const enum`:**
  - TypeScript `enum` генерирует лишний рантайм-код, ухудшает tree-shaking и имеет проблемы совместимости с одномодульными сборщиками (Vite/Astro/esbuild при `isolatedModules`).
- **Строковые Union Types — по умолчанию:**
  ```ts
  export type OrderStatus = 'pending' | 'processing' | 'completed';
  export type ThemeMode = 'light' | 'dark' | 'system';
  ```
- **Объекты `as const` — если значения нужны в рантайме:**
  ```ts
  export const ORDER_STATUS = {
    Pending: 'pending',
    Processing: 'processing',
    Completed: 'completed',
  } as const;

  export type OrderStatus = (typeof ORDER_STATUS)[keyof typeof ORDER_STATUS];
  ```

### 5. Экспорт и организация Barrel-файлов

- **Именованные экспорты (`Named Exports`) — стандарт по умолчанию:**
  - Все функции, утилиты, сервисы и типы экспортируются именованно:
    ```ts
    export function formatDate(date: Date): string { ... }
    export function formatPrice(amount: number): string { ... }
    ```
- **Default Export — только где требует фреймворк:**
  - Страницы в Astro (`.astro`) и Next.js App Router (`page.tsx`, `layout.tsx`, `error.tsx`).
  - Конфигурационные файлы (`astro.config.ts`, `vitest.config.ts`, `playwright.config.ts`, `eslint.config.mjs`).
  - В прикладных модулях и утилитах `default export` **запрещен**.
- **Политика Barrel-файлов (`index.ts`):**
  - Разрешены **только как явные фасады** на границах изолированных модулей/фичей (`src/features/lead-form/index.ts`).
  - **Запрещен `export *`:** только контролируемый именованный реэкспорт.
  - **Запрещены мега-баррели:** недопустимо делать свалки `src/utils/index.ts`, затягивающие весь бандл и провоцирующие циклические зависимости.
  - Внутри одного модуля файлы импортируют друг друга напрямую по локальным путям (`./api`), а не через собственный `index.ts`.

---

### 6. Объявление функций

- **`function` declaration — для верхнеуровневых чистых утилит и сервисов:**
  ```ts
  export function formatDate(date: Date): string {
    return new Intl.DateTimeFormat('ru-RU').format(date);
  }
  ```
  - Преимущества: явное имя в стектрейсах и профайлере, естественный hoisting (вспомогательные мелкие функции можно убирать в низ файла).
- **Стрелочные функции (`const fn = () =>`) — строго для локального контекста:**
  - Внутренние обработчики и замыкания.
  - Коллбэки методов массивов (`items.map(item => ...)`).

### 7. Именование файлов, сущностей и переменных

#### Файловая структура:
- **Утилиты, сервисы, константы:** строго `kebab-case` (`format-date.ts`, `api-client.ts`, `query-client.ts`).
- **Типы, схемы, сторы и ключи запросов:** `kebab-case` с суффиксом роли (`lead.types.ts`, `lead.schema.ts`, `cart.store.ts`, `product.keys.ts`).
- **Директории:** строго `kebab-case` во всем проекте.

#### Переменные и свойства:
- **Булевы флаги:** обязательный глагольный префикс:
  - `is...` — состояние объекта (`isOpen`, `isLoading`, `isValid`).
  - `has...` — наличие свойства/связи (`hasError`, `hasChildren`).
  - `can...` — возможность действия (`canSubmit`, `canClose`).
  - `should...` — условие исполнения (`shouldRender`, `shouldRefetch`).
  - *Запрещены:* одиночные прилагательные без префикса (`open`, `loading`, `error` для булевых значений).
- **Коллекции и массивы:** строго множественное число (`users`, `products`) либо суффикс словаря (`usersById`, `statusToColorMap`). Запрещено: `userList`, `dataArray`.
- **Константы:**
  - Глобальные неизменяемые константы конфигурации: `SCREAMING_SNAKE_CASE` (`API_RETRY_DELAY`, `DEFAULT_PAGE_LIMIT`).
  - Локальные константы внутри функций: `camelCase` (`const threshold = 10;`).

#### Функции и методы:
- Обязательный глагол в инфинитиве, отражающий суть:
  - `get...` — синхронное получение данных / геттер.
  - `fetch...` — асинхронный сетевой запрос.
  - `format...` / `calculate...` — чистые вычислительные преобразования.
  - `validate...` / `check...` — логические проверки.
  - `create...`, `update...`, `delete...` — мутации данных.

### 8. Импорты и порядок сортировки

- **Обязательный `import type`:** любые типы и интерфейсы импортируются исключительно с ключевым словом `type`. Это гарантирует полное удаление импорта из рантайма и предотвращает циклические зависимости.
- **Группировка импортов (ровно 1 пустая строка между группами):**
  1. Внешние библиотеки и вендоры (`zod`, `nanostores`).
  2. Внутренние модули по путям-алиасам (`@/shared/...`, `@/features/...`, `@/widgets/...`).
  3. Относительные локальные импорты (`./types`, `./utils`).
- **Автоматический контроль:** порядок проверяет `perfectionist/sort-imports`, форму `import type` — `@typescript-eslint/consistent-type-imports`; исправление командой `eslint --fix` (конфиг — [docs/setup.md](../setup.md) §2.4).

### 9. Обработка ошибок и асинхронность

- **Типизация ошибок:** блок catch всегда типизирует ошибку как `unknown`:
  ```ts
  try {
    // ...
  } catch (error: unknown) {
    const message = error instanceof Error ? error.message : 'Неизвестная ошибка';
    console.error(message); // клиентское логирование: ADR 0014 §5
  }
  ```
- **Запрет пустых блоков `catch`:** молчаливое подавление ошибок (silent fail) категорически запрещено.
- **Асинхронный код:** строго синтаксис `async / await`. Цепочки `.then().catch()` запрещены в прикладном коде.
- **Безопасные обертки над Web API:**
  - Доступ к `localStorage` / `sessionStorage` и вызовы `JSON.parse` должны быть изолированы в безопасных утилитах с обработкой исключений.
- **Сетевые запросы (`fetch`):**
  - Обязательная проверка `if (!response.ok)` перед чтением тела ответа.
  - Валидация структуры ответа через схему Zod (`userSchema.parse(await response.json())`).

### 10. Vanilla JS, Web API и стратегия загрузки скриптов

- **Селекторы в DOM:** поиск элементов в JS выполняется **строго по `data-*` атрибутам** (`[data-menu-trigger]`, `[data-modal-target]`), а не по классам стилей (`.btn-active`). Стили и поведение должны быть полностью развязаны.
- **Запрет Non-Null Assertion (`!`):**
  ```ts
  // ❌ Запрещено:
  const btn = document.querySelector('[data-trigger]')!;

  // ✅ Правильно:
  const btn = document.querySelector<HTMLButtonElement>('[data-trigger]');
  if (!btn) return;
  ```
- **Защита от повторной инициализации:** на узлах DOM выставляется маркер (`element.dataset.initialized = 'true'`).
- **Очистка ресурсов:** при динамическом монтировании или навигации обязательно вызывать `removeEventListener` и `observer.disconnect()`.
- **Стратегия загрузки скриптов:**
  - **Статический импорт в бандле:** для базового легковесного UI, требующего немедленного отклика (бургер-меню, аккордеоны, табы, закрытие плашек).
  - **Динамический импорт (`await import(...)`):** строго для тяжелых библиотек или редких сценариев по наступлению события (маски ввода, тяжелые карусели, полноэкранные галереи).
  - **Инлайн в `<head>`:** крошечный синхронный скрипт инициализации темы для предотвращения мигания фона (FOUC).

### 11. Работа с `null`, `undefined` и опциональными значениями

- **`undefined` — только для опциональности:**
  - Непереданные аргументы функций (`options?: RequestOptions`).
  - Неинициализированные локальные переменные (`let timer: ReturnType<typeof setTimeout> | undefined;`).
- **`null` — только для явного отсутствия данных в моделях и внешних контрактах:**
  - Модели данных, ответы API и структуры БД, где значение сброшено или отсутствует (`avatarUrl: string | null`).
  - Нативные возвраты DOM API (`document.querySelector` возвращает `Element | null`).
- **Запрет смешанных типов `T | null | undefined`:** тип поля обязан быть однозначным (либо опционален, либо nullable).
- **Оператор Nullish Coalescing (`??`) вместо `||`:**
  - Для задания дефолтных значений строк, чисел и булевых типов строго используется оператор `??`.
- **Явные проверки на пустоту:** запрещено использовать неявное `if (!value)` для числовых или булевых значений (проверять строго: `if (value === null)`, `if (value === undefined)` или `if (typeof value === 'number')`).

### 12. Иммутабельность и методы массивов (ES2023)

- **Запрет мутации параметров функций:** входящие объекты и массивы трактуются как `readonly`.
- **Запрет мутирующих методов массивов:**
  - Запрещены методы `.sort()`, `.reverse()`, `.splice()`.
  - Использовать современные нативные копирующие методы ES2023: `.toSorted()`, `.toReversed()`, `.toSpliced()`.
- **Удаление полей объектов:** запрещен оператор `delete obj[key]`. Использовать rest-деструктуризацию (`const { secret, ...safeData } = data;`).
- **Аннотации `readonly`:** для неизменяемых массивов и константных параметров функций применять `readonly T[]`.

### 13. Конфигурация и переменные окружения (Environment Variables)

- **Запрет прямого чтения `import.meta.env` и `process.env`:** в коде модулей, утилит и страниц запрещено обращаться к переменным окружения напрямую.
- **Централизованный модуль конфигурации:**
  - Единая точка входа для публичных переменных — `src/shared/config/env.ts`; модули импортируют строго типизированный объект `import { env } from '@/shared/config/env';`.
  - **Astro:** все переменные объявляются в `env.schema` файла `astro.config.ts` ([docs/setup.md](../setup.md) §3.1), Astro проверяет их при сборке. `env.ts` собирает публичные значения из `astro:env/client`:
    ```ts
    // src/shared/config/env.ts
    import { PUBLIC_API_URL, PUBLIC_GA_ID, PUBLIC_SITE_URL, PUBLIC_YM_ID } from 'astro:env/client';

    export const env = { PUBLIC_API_URL, PUBLIC_GA_ID, PUBLIC_SITE_URL, PUBLIC_YM_ID } as const;
    ```
  - **Next.js:** `env.ts` валидирует `process.env` схемой Zod и экспортирует тот же объект `env` (исключение из запрета прямого чтения — только внутри `env.ts`).
  - Приложение немедленно падает при сборке или запуске, если отсутствует обязательная переменная или нарушен ее формат.
- **Серверные секреты:**
  - В Astro секреты (токены интеграций) объявляются в `env.schema` файла `astro.config.ts` с `access: 'secret'` и читаются из `astro:env/server` только в серверном коде (эндпоинты `src/pages/api/*`). В клиентский код они не попадают.
  - Исключение из запрета чтения окружения: конфигурационные файлы сборки (`astro.config.ts`, `next.config.ts`).

### 14. Словари, структуры данных и итерация по объектам

- **Запрет слепого `Record<string, T>`:**
  - Использовать конкретные литеральные ключи или `Partial<Record<Status, Color>>`.
  - При использовании динамических строковых ключей включать `noUncheckedIndexedAccess` и явно указывать `Record<string, T | undefined>`.
- **Безопасный доступ к ключам объекта:**
  - Использовать типизированную утилиту `getKeys(obj)` вместо прямого каста `Object.keys(obj) as (keyof T)[]`:
    ```ts
    export function getKeys<T extends object>(obj: T): (keyof T)[] {
      return Object.keys(obj) as (keyof T)[];
    }
    ```
- **Выбор между объектом и `Map`:**
  - Статичные наборы, маппинги статусов и конфиги: объекты `as const`.
  - Динамические коллекции с частым добавлением/удалением ключей или кешированием: строго нативный `Map<K, V>`.

### 15. Итерация и циклы: контроль асинхронности

- **Тотальный запрет `async` внутри `.forEach()`:**
  - Метод `.forEach()` не ожидает промисы и приводит к скрытым утечкам и гонкам данных.
  - Для последовательной асинхронной обработки: строго цикл `for (const item of items) { await ... }`.
  - Для параллельной асинхронной обработки: строго `await Promise.all(items.map(async (item) => ...))` или `Promise.allSettled`.
- **Трансформация данных:**
  - Простые проекции: чистые методы `.map()`, `.filter()`, `.find()`, `.some()`, `.every()`.
- **Ограничение на `.reduce()`:**
  - Разрешен только для элементарных математических сумм/произведений в 1–2 строки.
  - Для группировки коллекций использовать нативный метод **`Object.groupBy()`** (ES2024) или явный цикл `for...of`.
