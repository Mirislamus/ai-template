# Инженерные стандарты дизайн-системы

Документ фиксирует фундаментальные правила визуальной системы, модульной сетки, семантических токенов, типографики и состояний интерфейса. Визуальная стилистика (конкретная палитра, фирменные шрифты) задается под проект, но инженерная база всегда неизменна.

---

## 1. Модульная сетка и система пространств (8pt Grid)

- **Базовый шаг:** все отступы (`margin`, `padding`, `gap`) кратны **8px**. Для компактных элементов и микро-отступов допускается полушаг **4px**.
- **Единицы измерения:** строго **пиксели (`px`)** через CSS-переменные. Использование `rem` и `em` для отступов запрещено.
- **Шкала пространственных токенов (`src/shared/styles/_tokens.scss`, эталонный файл — [setup/frontend.md](setup/frontend.md) §4):**
  ```css
  :root {
    --space-1: 4px;    /* микро-отступы, бейджи, иконки */
    --space-2: 8px;    /* плотные списки, зазоры кнопок */
    --space-3: 12px;   /* внутренние отступы инпутов */
    --space-4: 16px;   /* базовый шаг контента, карточки */
    --space-5: 20px;   /* промежуточный шаг */
    --space-6: 24px;   /* поля форм, сетка колонок */
    --space-8: 32px;   /* расстояние между блоками */
    --space-10: 40px;  /* отступы подзаголовков */
    --space-12: 48px;  /* вертикальные отступы секций (мобильные) */
    --space-16: 64px;  /* вертикальные паддинги секций (десктоп) */
    --space-20: 80px;  /* просторные промо-интервалы */
    --space-24: 96px;  /* крупные интервалы лендинга */
    --space-32: 128px; /* максимальные секционные разделители */
  }
  ```
- **Запрет:** категорически запрещены несистемные значения (`margin: 13px;`, `padding: 27px;`). Использовать строго токены `var(--space-*)`.

## 2. Адаптивность, брейкпоинты и контейнеры

- **Подход верстки:** строго **Mobile-First** (`min-width`). Стили пишутся от базового мобильного экрана к десктопному.
- **Шкала контрольных точек (единая для проекта, [ADR 0003](decisions/frontend/0003-scss-standards.md) §1):**
  - `360px` — нижняя граница поддержки. Это не брейкпоинт: базовые стили пишутся для нее и для более широких экранов.
  - `sm: 576px` — крупные фаблеты и мобильный ландшафт.
  - `md: 768px` — планшеты (граница переключения мобильного меню на десктопную навигацию).
  - `lg: 1024px` — ноутбуки и небольшие экраны.
  - `xl: 1280px` — стандартные десктопные мониторы.
  - `2xl: 1440px` — широкоформатные экраны.
  - Медиазапросы пишутся только через миксины `up(name)` и `down(name)` из `_tools.scss`.
- **Контентный контейнер (`.container`):**
  - Максимальная ширина: `max-width: var(--container-max-width)` (1280px), центрирование `margin-inline: auto;`.
  - Безопасные боковые поля `--container-gutter`, исключающие прилипание текста к рамкам: 16px (`--space-4`) до `md`, 32px (`--space-8`) от `md`.
- **Запрет произвольных брейкпоинтов:** запрещено вставлять случайные медиа-запросы (`@media (max-width: 843px)`).

## 3. Семантическая архитектура цветов и темы (Theming)

- **Принцип разделения:** компоненты не используют прямые HEX-коды (`#ffffff`, `#111827`), а ссылаются на семантические роли цвета.
- **Базовые семантические слоты токенов:**
  - **Фоновые роли (Backgrounds):**
    - `--color-bg-page` — основной фон страницы (холст).
    - `--color-bg-surface` — фон приподнятых карточек, модальных окон, дропдаунов.
    - `--color-bg-muted` — второстепенный фон (серые секции, плашки, чередующиеся строки).
  - **Текстовые роли (Typography):**
    - `--color-text-primary` — основной текст и главные заголовки.
    - `--color-text-secondary` — пояснения, подзаголовки, параграфы (контраст не ниже 4.5:1 к фону по WCAG AA).
    - `--color-text-muted` — плейсхолдеры, сноски, второстепенные даты.
    - `--color-text-inverse` — текст на акцентном темном/ярком фоне (например, белый текст на цветной кнопке).
  - **Бордеры и линии (Borders):**
    - `--color-border-subtle` — тонкие разделители, сетки, контуры карточек.
    - `--color-border-strong` — активные рамки инпутов, акценты.
  - **Акцент и статусы (Brand & Status):**
    - `--color-accent` — основной фирменный цвет бренда и главных CTA-кнопок.
    - `--color-accent-hover` — состояние наведения акцентных элементов.
    - `--color-status-error` — ошибки валидации, деструктивные действия.
    - `--color-status-success` — индикаторы успешных действий.
- **Поддержка темной темы (Dark Mode):**
  - Реализуется через переопределение значений тех же самых переменных в селекторе `[data-theme="dark"]`:
    ```css
    :root {
      --color-bg-page: #fff;
      --color-text-primary: #0f172a;
      --color-border-subtle: #e2e8f0;
    }

    [data-theme="dark"] {
      --color-bg-page: #0b0f19;
      --color-text-primary: #f8fafc;
      --color-border-subtle: #1e293b;
    }
    ```
  - Код компонентов в SCSS Modules остается неизменным и не дублируется под разные темы.

## 4. Типографика: резиновые заголовки, стабильный текст и балансировка строк

- **Резиновые заголовки через нативный `clamp()`:**
  - Крупные заголовки плавно масштабируются в зависимости от ширины экрана без ступенчатых медиа-запросов:
    ```css
    :root {
      --font-size-h1: clamp(32px, 4vw + 16px, 56px);
      --font-size-h2: clamp(24px, 2.5vw + 14px, 40px);
      --font-size-h3: clamp(20px, 1.5vw + 14px, 28px);
    }
    ```
- **Стабильный фиксированный текст (Защита от микротекста и зума на iOS):**
  - Основной контент, формы и кнопки используют фиксированные пиксели:
    - `--font-size-base: 16px;` — базовый размер параграфов и полей ввода (размер менее 16px на мобильном Safari вызывает принудительный зум экрана).
    - `--font-size-sm: 14px;` — вторичные пояснения, подписи к полям.
    - `--font-size-xs: 12px;` — мелкие сноски, бейджи, теги.
- **Балансировка строк (Text Wrap Balance & Pretty):**
  - **Для заголовков (`h1`–`h4`):** свойство `text-wrap: balance;`. Автоматически выравнивает длину строк заголовка, предотвращая появление сиротливых коротких строк из одного слова.
  - **Для основного текста и абзацев:** свойство `text-wrap: pretty;`. Предотвращает выпадение одиночного последнего слова на новую строку (типографические «висячие строки» / orphans).
- **Высота строки (Line-Height):**
  - **Для заголовков (`h1`–`h3`):** плотный интерлиньяж **1.1 – 1.25**, токен `--line-height-tight: 1.15` (предотвращает распад многострочных заголовков).
  - **Для основного текста:** комфортный интерлиньяж **1.5 – 1.6**, токен `--line-height-normal: 1.55`; для подзаголовков — `--line-height-snug: 1.3`.
- **Ограничение длины строки (Measure):**
  - Длина текстовых параграфов не должна превышать **65–75 символов** (около 650–700px), чтобы глаз не уставал при переносе взгляда.

## 5. Компонентные токены: радиусы, тени и слои

- **Радиусы скруглений (`border-radius`):**
  ```css
  :root {
    --radius-sm: 4px;   /* бейджи, теги */
    --radius-md: 8px;   /* инпуты, стандартные кнопки */
    --radius-lg: 16px;  /* карточки, модальные окна */
    --radius-xl: 24px;  /* крупные промо-секции */
    --radius-full: 9999px; /* круглые аватары, pills-кнопки */
  }
  ```
- **Шкала теней (Elevation):**
  - Минималистичные, естественные тени с низким контрастом (альфа-канал 4–8%):
    - `--shadow-sm` — плоские карточки при ховере.
    - `--shadow-md` — выпадающие списки, поповеры.
    - `--shadow-lg` — модальные окна, мобильные шторки.
- **Шкала Z-Index:** строго соответствует [ADR 0003](decisions/frontend/0003-scss-standards.md) (от `--z-base: 1` до `--z-tooltip: 800`). Запрещены голые произвольные числа.

## 6. Комфорт тач-устройств и естественные отступы

- **Отказ от искусственных хаков:**
  - Запрещено принудительно раздувать геометрию ссылок или иконок через громоздкие `min-width: 44px; min-height: 44px;`, ломающие визуальную эстетику меню и тулбаров.
- **Естественные зоны нажатия (Natural Touch Clearance):**
  - Достаточная площадь взаимодействия формируется **естественными внутренними отступами (padding)** самого интерактивного блока (например, кнопка с паддингами `var(--space-3) var(--space-4)`, то есть 12px 16px).
  - Для изолированных иконок и стрелок используется компактный контейнер с внутренним зазором (например, иконка 20px с внутренними паддингами 8px дает аккуратный кликабельный блок 36×36 px).
  - Между соседними интерактивными элементами всегда задается минимальный зазор (`gap: var(--space-2)` от 8px), чтобы исключить случайные ложные нажатия на смартфонах.
- **Текстовая навигация:**
  - Ссылки в меню и списках сохраняют компактный естественный вид, а удобство клика обеспечивается интерлиньяжем (`line-height: 1.5`) и отступами между пунктами.

## 7. Матрица состояний интерактивных элементов (Interactive States)

Термины проекта различают три набора состояний: **состояния элемента** (этот раздел), **состояния формы** (Idle, Submitting, Success, Error, Disabled — [ADR 0008](decisions/frontend/0008-forms-and-api.md) §5) и **состояния данных** (Loading, Empty, Error, Success — [page-template](pages/page-template.md)).

Каждый кликабельный элемент (кнопка, ссылка, инпут, карточка) обязан явно обрабатывать 6 состояний:

1. **Default (Покой):** базовый вид компонента.
2. **Hover (Наведение):**
   - Плавное изменение фона, границы или тени через токены анимации (`transition: background-color var(--motion-fast) var(--ease-out), box-shadow var(--motion-fast) var(--ease-out);`).
   - Стили hover изолируются миксином `@include hover` ([ADR 0003](decisions/frontend/0003-scss-standards.md) §5), чтобы на смартфонах не залипали стили наведения при тапе.
3. **Active (Нажатие):**
   - Осязаемый тактильный отклик: легкий микро-сдвиг (`transform: scale(0.98);` или `transform: translateY(1px);`).
4. **Focus-Visible (Клавиатурный фокус):**
   - Строго селектор `:focus-visible` с контрастным кольцом (`@include focus-ring;` — `outline: 2px solid var(--color-accent); outline-offset: 2px;`). Запрещен `outline: none` без замены.
5. **Disabled (Неактивно):**
   - Нативный атрибут `disabled` (кнопки, поля) или `aria-disabled="true"` (ссылки), визуальное приглушение `opacity: 0.5;` и `cursor: not-allowed;`.
   - `pointer-events: none` не используется: при нем курсор `not-allowed` не отображается.
6. **Loading (Загрузка):**
   - Текст скрывается или заменяется спиннером, при этом **габариты кнопки жестко сохраняются** (запрет схлопывания и дерганья размеров при отправке формы).

## 8. Защита от переполнения текста (Text Truncation & Overflow)

В интерфейсе любой динамический текст из API, базы данных или CMS может превысить ожидания дизайнера. Верстка обязана быть устойчива к длинным строкам:

- **Безопасный перенос длинных слов и ссылок:**
  - Для всех текстовых контейнеров и параграфов:
    ```scss
    overflow-wrap: anywhere;
    ```
  - Исключает распирание карточек или появление горизонтального скролла из-за длинных URL или email.
- **Однострочное обрезание с многоточием (Ellipsis):**
  - Для заголовков карточек или таблиц в одну строку:
    ```scss
    overflow: hidden;
    text-overflow: ellipsis;
    white-space: nowrap;
    ```
- **Многострочный зажим текста (Line-Clamp):**
  - Для анонсов статей, отзывов и карточек товаров:
    ```scss
    @include line-clamp(3); // миксин из _tools.scss: ограничение ровно в 3 строки
    ```

## 9. Анти-шаблоны (проверяются при ревью)

Признаки «дизайна на автопилоте» не допускаются, если их не задают макет, брендбук или утвержденный план (ниже). Список — единственный источник правил вкуса: собственные правила и анти-шаблоны дизайн-навыков его не заменяют и не дополняют ([docs/skills.md](skills.md) §2).

**Цвет и поверхности (§3, §5):**
1. Фон секций — только токены `--color-bg-*`. Декоративные градиенты, градиентные пятна и полупрозрачные размытые панели (glassmorphism) без функциональной причины не используются.
2. `--color-accent` выбирается под проект: синий `#3b82f6`, фиолетовый и другие стандартные цвета UI-библиотек как цвет бренда не используются.
3. Тени — только `--shadow-sm/md/lg`, не больше двух уровней на одном экране; тени и скругления не ставятся на каждый элемент подряд.
4. Радиус берется из шкалы §5 по уровню элемента: один радиус на всех элементах не используется.

**Секции и первый экран (§1–2, [паспорта страниц](pages/page-template.md)):**
5. Структура секции выводится из ее содержания в паспорте страницы; сетка из трех одинаковых карточек «иконка + заголовок + текст» не используется как универсальное решение.
6. Первый экран показывает оффер и CTA из паспорта самым характерным для продукта способом: заголовком, изображением или демонстрацией. Шаблон «крупная цифра с подписью, ряд статистики и градиентный акцент» не используется.
7. Весь текст по центру не выравнивается: длинные абзацы — по левому краю.

**Типографика (§4, [content.md](content.md)):**
8. Иерархия заголовков читается без цвета: уровни различаются токенами `--font-size-h1…h3` и весом.
9. Подписи-«надзаголовки» капсом с разрядкой над каждым заголовком и служебные подписи без информации не используются.
10. Одно слово или фраза в заголовке не выделяются курсивом, жирным или цветом.
11. Нумерация `01 / 02 / 03` — только для последовательностей (шаги процесса, этапы, хронология) и только в списке `<ol>` ([ADR 0002](decisions/frontend/0002-html-standards.md) §6).
12. Шаблонные мелочи не используются: служебные строки через средние точки («A · B · C»), подписи вида «СЛОВО — фрагмент», стрелка «→» в конце текста ссылок и кнопок, моноширинный шрифт для мелких подписей данных.

**Контент и графика:**
13. Цифры, счетчики, отзывы и логотипы клиентов — только проверяемые факты ([content.md](content.md) §2).
14. Иконки — `lucide-react` или SVG по [ADR 0007](decisions/frontend/0007-assets-and-media.md) §4; эмодзи вместо иконок и иллюстраций не используются.

**Движение ([ADR 0017](decisions/frontend/0017-motion-and-animations.md)):**
15. Каждое движение объясняет изменение состояния, значения — токены `--motion-*` и `--ease-out`. Появление при прокрутке (`data-reveal`) не ставится на каждую секцию и не применяется на первом экране.

**Стилистика:**
16. Готовые «AI-стилистики» не выбираются по умолчанию: кремовый фон с контрастным serif-заголовком и терракотовым акцентом; почти черный фон с одним кислотно-зеленым или красно-оранжевым акцентом; газетная верстка с тонкими линейками, нулевыми радиусами и плотными колонками.

### Порядок выбора палитры и шрифтов под проект

Палитра и шрифты выбираются один раз на старте проекта; результат — значения токенов в `_tokens.scss` (эталон — [setup/frontend.md](setup/frontend.md) §4):

1. **Источник.** Если в разделе «Дизайн» [PRODUCT.md](../PRODUCT.md) указан макет Figma или брендбук, значения переносятся из них без изменений, остальные шаги не нужны.
2. **План до кода.** Готовится по PRODUCT.md (тематика, аудитория, оффер) и паспортам страниц ([docs/pages/](pages/page-template.md)); недостающие данные запрашиваются у пользователя:
   - **цвет** — значение HEX или RGB для каждого семантического слота §3 в светлой и темной теме ([ADR 0003](decisions/frontend/0003-scss-standards.md) §4), контраст текста — по [quality.md](quality.md) §2;
   - **шрифты** — одно или два семейства с ролями (`--font-sans` и при необходимости шрифт заголовков, явно отличающийся), с символами всех языков сайта из PRODUCT.md и лицензией на самохостинг ([ADR 0007](decisions/frontend/0007-assets-and-media.md) §3); размеры — по шкале §4;
   - **раскладка** — для каждой страницы последовательность секций из ее паспорта, ASCII-схема на 360px и от `lg`, правило выравнивания; контейнер и отступы — токены §1–2;
   - **принципы** — 2–3 правила, которые отличают проект, сформулированные через токены и компоненты (например, «акцент только на основном CTA»).
3. **Самопроверка.** План сверяется с анти-шаблонами этого раздела и с тем, что получилось бы для любого похожего проекта. Шаблонные части заменяются, причина замены указывается.
4. **Подтверждение.** План показывается пользователю; значения попадают в `_tokens.scss` только после его подтверждения ([AGENTS.md](../AGENTS.md): стилистика не меняется по собственной инициативе).
