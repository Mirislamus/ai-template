# Регламент задач и субагентов (docs/agents.md)

Документ определяет оценку сложности задач, порядок их разбиения и хранения, состав субагентов и правила их запуска. Общие правила поведения агента — [AGENTS.md](../AGENTS.md), навыки — [docs/skills.md](skills.md).

---

## 1. Уровни сложности

Шкала одна: Low, Medium, High, XHigh. Уровень задачи — самый высокий из сработавших признаков; неопределенность требований поднимает уровень на один.

| Уровень | Признаки | Примеры |
|---|---|---|
| Low | Один модуль или файл, решение очевидно, поведение не меняется | Текст, стиль, опечатка, конфиг по эталону из [docs/setup/](setup/common.md) |
| Medium | Один слой FSD-Lite ([ARCHITECTURE.md](../ARCHITECTURE.md)), до ~5 файлов, есть спецификация и аналоги в коде | Виджет по паспорту страницы, UI-компонент |
| High | Несколько слоев или `apps/web` + `apps/api`; данные, формы, авторизация; внешняя интеграция; изменение публичного контракта | Форма заявки с отправкой в CRM, эндпоинт API с клиентом |
| XHigh | Архитектурная развилка, нет подходящего ADR, миграция данных, безопасность, трудноуловимый баг; задача не умещается в одну сессию | Выбор способа авторизации, перенос данных между схемами |

- Предварительный уровень ставит основной агент, когда берет задачу в работу.
- Задачи уровня High и XHigh, а также планирование целого этапа (например, всех страниц по утвержденным паспортам) основной агент передает `planner`.

---

## 2. Процесс по уровню

| Уровень | Порядок работы | Карточка | Исполнитель |
|---|---|---|---|
| Low | Выполняется сразу | Не нужна, только строка в индексе | Основной агент или `*-dev` |
| Medium | Короткий план в чате, затем выполнение | Нужна | `*-dev` |
| High | `planner` готовит карточку → подтверждение пользователя → выполнение | Нужна | `*-dev-deep` |
| XHigh | Обязательная попытка разбить на подзадачи High и ниже; неделимая задача выполняется после плана и подтверждения пользователя | Нужна | `*-dev-deep` |

Правила [AGENTS.md](../AGENTS.md) «Сомнения и решения» действуют на любом уровне: развилка в поведении, дизайне, архитектуре или scope выносится на вопрос пользователю.

---

## 3. Разбиение на подзадачи

- Подзадача дает один проверяемый результат, относится к одному слою и имеет одного исполнителя.
- Размер подзадачи — не больше одного атомарного коммита ([ADR 0011](decisions/common/0011-git-workflow-and-commits.md) §2).
- Каждая подзадача оценивается отдельно; подзадача уровня XHigh разбивается дальше, если это возможно.
- Зависимости между подзадачами указываются явно; подзадача начинается после завершения всех, от которых зависит.
- Критерии готовности берутся из источников истины (PRODUCT.md, паспорт страницы, ADR) со ссылкой, а не придумываются.

---

## 4. Хранение задач

- [docs/tasks.md](tasks.md) — индекс: номер, задача, уровень, статус, ссылка на карточку.
- Карточка задачи уровня Medium и выше — `docs/tasks/NNN-slug.md` по шаблону [docs/tasks/task-template.md](tasks/task-template.md). `NNN` — сквозной трехзначный номер из индекса, `slug` — краткое название латиницей в kebab-case.
- Статусы карточки и подзадач обновляются после каждой подзадачи; индекс — при смене статуса задачи. [STATE.md](../STATE.md) обновляется по правилам [AGENTS.md](../AGENTS.md).

## 5. Субагенты

Роли описаны в `.claude/agents/*.md`. Claude Code подключает их нативно: модель, effort и инструменты задаются во frontmatter файла. Другие AI-агенты выполняют роль сами, читая этот раздел и тело файла роли как инструкцию.

| Агент | Назначение | Модель / effort | Права |
|---|---|---|---|
| `planner` | Оценка, разбиение, черновик карточки | opus / high | Только чтение; карточку записывает основной агент |
| `explorer` | Поиск по коду и документации | haiku / low | Только чтение |
| `frontend-dev` | Фронтенд уровня Low и Medium | sonnet / medium | Изменение файлов |
| `frontend-dev-deep` | Фронтенд уровня High и XHigh | opus / xhigh | Изменение файлов |
| `backend-dev` | Бэкенд уровня Low и Medium | sonnet / medium | Изменение файлов |
| `backend-dev-deep` | Бэкенд уровня High и XHigh | opus / xhigh | Изменение файлов |
| `reviewer` | Ревью diff по стандартам и спецификации (этап `$code-review` из [docs/skills.md](skills.md) §3) | opus / high | Только чтение и Git-команды чтения |
| `qa` | Проверки из [AGENTS.md](../AGENTS.md) «Тесты и проверки», Definition of Done ([ADR 0014](decisions/common/0014-testing-and-qa.md) §4), браузер через `$agent-browser` | sonnet / medium | Запуск команд; код не изменяет |

- Исполнитель выбирается по слою подзадачи, тир (`*-dev` или `*-dev-deep`) — по ее уровню. Модель при вызове не переопределяется: уровень выбирает файл исполнителя.
- `backend-dev` и `backend-dev-deep` используются, только если бэкенд выбран в PRODUCT.md ([ADR 0019](decisions/backend/0019-backend-architecture.md) §1).
- Модели указаны алиасами (`opus`, `sonnet`, `haiku`) и следуют за актуальными версиями. Если модель не поддерживает заданный effort, Claude Code понижает его до ближайшего доступного ([документация](https://code.claude.com/docs/en/model-config)).

## 6. Правила запуска

- Пишущий субагент запускается только по подзадаче из карточки. Для High и XHigh карточка должна быть подтверждена пользователем; для Low и Medium подтверждением служит прямой запрос пользователя.
- Пишущие субагенты работают последовательно в одном рабочем дереве. `explorer` и `reviewer` запускаются без отдельного согласования и могут работать параллельно.
- Субагент получает путь к карточке и номер подзадачи, сам читает карточку и ее источники и не выходит за scope подзадачи.
- Субагент не выполняет commit, push, merge и другие Git-операции записи, не добавляет зависимости и не меняет внешние сервисы. На развилке, требующей решения пользователя, он останавливается и возвращает вопрос основному агенту.
- Субагент возвращает отчет: что сделано, измененные файлы, запущенные проверки и их результат, использованные скилы, блокеры.
- Основной агент отвечает за итоговые проверки, обновление карточки и индекса и итоговый отчет пользователю.

---

## 7. Отчетность

- На старте задачи агент вместе с навыками ([docs/skills.md](skills.md) §1) объявляет уровень задачи.
- В итоговом отчете [AGENTS.md](../AGENTS.md) пункт «Уровень и субагенты» содержит итоговый уровень и список привлеченных субагентов с их моделями и результатом (или «Субагенты не привлекались»).
